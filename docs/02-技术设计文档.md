# 02 · 技术设计文档

> 《宝可梦·晶穴深处》技术架构 · v0.1（M0）· 2026-11-02
> 版本基线（调研于 2026-11-02）：three **r187**（2026-10-30 发布）、pmndrs/postprocessing **6.39.x**（peer 允许 <0.188）、N8AO **2.x**（可选）。

## 1. 技术栈与基线

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 渲染 | three r187 **WebGLRenderer**（vendored 到 `vendor/three/`） | WebGPURenderer 虽有 WebGL2 回退，但 pmndrs/postprocessing **不支持 WebGPU**、TSL 生态仍在变动；首发锁 WebGL2，渲染收敛在薄适配层 `gfx/` 内，未来可切 |
| 后处理 | pmndrs/postprocessing 6.39.x（vendored `vendor/postprocessing/`）+ N8AO（可选，画质高档才启用） | Bloom(mipmapBlur)/DoF/TiltShift/Vignette/ToneMapping(AgX)/SMAA/Noise 全齐；ESM 可走 import map |
| 模块方案 | 浏览器原生 ES 模块 + **import map**（`three`、`postprocessing` 映射到 vendor 目录） | 无构建链；import map 支持面 Chrome 89+/Safari 16.4+/Firefox 108+，足够 |
| 依赖获取 | curl 从 unpkg/jsDelivr 拉**固定版本**的官方 ESM 构建（`three.module.min.js`、postprocessing `build/index.js`） | 本机没有可用的 npm，也不需要；版本号写进 `vendor/VERSIONS` |
| 语言/测试 | 原生 JS（ES2022）+ `node --test`；本机 node 用 Lark 沙盒运行时（v22） | 与前两作工作流一致 |
| 图像处理 | Python 3 + Pillow（本机已装 11.3） | 图集打包、图标放大（gym-pixel 同款） |
| 本地服务 | `python3 tools/serve.py 8349`（no-store + 云榜 API，沿用 gym-run 方案） | 端口分配：gym-run 8347 / gym-pixel 8348 / **本作 8349** |
| 托管 | GitHub Pages 纯静态 + PWA（sw 缓存，tools/make-sw.sh 生成） | 同前两作 |

**画质三档**（运行时探测 + 手动切换，设置持久化）：

| 档 | 后处理 | 分辨率 | 其他 |
| --- | --- | --- | --- |
| 高 | 全链（N8AO+DoF+Bloom+ToneMap+Vignette+SMAA） | devicePixelRatio≤2 | 阴影 2048 |
| 中 | 去 N8AO/DoF | dpr≤1.5 | 阴影 1024 |
| 低 | 仅 ToneMap+SMAA | dpr=1 | 阴影关，点光池减半 |

首帧先按 `navigator.hardwareConcurrency` + 首个房间 200 帧耗时自动判档。

## 2. 架构总览

**模拟与渲染完全分离**（ADR-6）：模拟层是纯数据变换（可在 node 里无头跑），渲染层只读状态快照。

```
┌─────────────────────────────── 浏览器 ───────────────────────────────┐
│  main.js  启动：manifest 加载 → 素材下载/解码 → boot(sim, gfx, ui)    │
│                                                                     │
│  ┌─ 数据层 data/ ──────────────┐   ┌─ 模拟层 sim/（纯函数，无 DOM）─┐ │
│  │ species.json enemies.json   │   │ 固定步长 60Hz：input→move→     │ │
│  │ moves.json items.json       │──▶│ collide→projectile→ai→wave→   │ │
│  │ typechart.json floors.json  │   │ pickup→fsm；状态可序列化       │ │
│  │ balance.json（热更调数值）   │   │ mulberry32 种子随机            │ │
│  └─────────────────────────────┘   └──────────────┬────────────────┘ │
│                                                  │ 状态快照/帧事件    │
│  ┌─ 渲染层 gfx/（three）─────────────────────────▼────────────────┐ │
│  │ 场景图（地面/墙/实体 billboard/灯光/粒子）+ 后处理链 + 相机      │ │
│  └──────────────────────────────┬────────────────────────────────┘ │
│  ┌─ UI 层 ui/（DOM+CSS）─────────▼──── HUD/菜单/图鉴/分享图 ───────┐ │
│  └────────────────────────────────────────────────────────────────┘ │
│  audio/  WebAudio 合成音 + 叫声解码缓存（ogg 解码失败静默降级）       │
└─────────────────────────────────────────────────────────────────────┘
```

模拟→渲染通信：每帧模拟产出**完整状态引用** + **事件列表**（`spawn/despawn/hit/die/pickup/roomchange/...`）；
渲染层按事件做特效（粒子/震屏/音效），按状态做插值绘制。UI 只在事件/状态摘要变化时重绘 DOM。

## 5. 模拟层设计

- **固定步长**：`dt=1/60`，累加器驱动；一帧最多补 4 步（防后台切回时雪崩），补不动就掉帧、不丢模拟；
- **确定性**：所有随机走 `rng.js`（可序列化 uint32 状态）；地图生成、掉落、金冠判定全部可由
  `(seed, 输入流)` 复现——挑战码/回放/测试都吃这个红利；
- **坐标约定**：模拟层是 2D 平面坐标 (x, y)，单位=tile；渲染层映射到 three 世界 (x, 0, y)
  （Y 轴向上，地面为 XZ 平面）；
- **实体=普通对象**（id、kind、pos{x,y}、半径、hp、fsm 状态、冷却表），数组桶分类
  （actors/projectiles/pickups/effects）；不用 class 继承树，行为按数据里的 family 字段查表分派；
- **碰撞**：圆形碰撞体 + 统一网格（房间战斗区 17×11 tile——以撒原版为 13×7，本作加宽以适配
  双摇杆走位与 16 texel 密度；1 tile = 1 世界单位 = 16 texel，见《03》）；
  弹×实体、实体×实体、实体×墙三张粗筛表；
- **房间状态机**：`enter → sealing → waves(1..2) → cleared(开门+掉落) → exited`；
  玩家跨门即进入邻房（以撒式：房与房在 3D 里复用同一个"盒子"，
  换房=换场景内容 + 0.3s 相机闪切遮罩）；
- **序列化**：`save = {v:1, seed, rngState, floor, roomGrid, player, inventory, flags}`，
  任意帧可存可读（挑战码=种子+元信息，不存输入流，防止码过长）。

## 6. 地图生成（以撒算法移植）

参考社区对以撒生成器的拆解（BorisTheBrave《Dungeon Generation in Binding of Isaac》与
Rebirth 逆向伪代码 wiki.gg/Level_Generation），按以下规格实现：

```
输入: rng, 目标房间数 target = min(20, 5 + floor(10×层号/3) + rand(0,1))
      （层1 = 8–9、层2 = 11–12、层3 = 15–16，与以撒 Repentance 公式一致）
网格: 13×13 cell（Repentance 同规格），中心 (6,6) 为出生房
流程:
  1. queue = [出生房]
  2. 取队首 cell 的 4 个邻居 n：
     a. n 越界或已占用 → 跳过
     b. n 的已占用邻居数（不含来源格）≥1 → 放弃   ← 防成环（Boris 原文："more than one filled neighbour"）
     c. 50% 概率直接放弃（让形状随机伸展）
     d. 否则放置 n 并入队；房间数达标即停
     （目标 >16 时按原版做法周期性把出生房重新入队）
  3. 重 roll（官方同款）：房间数不足 target，或 Boss 房与出生房相邻 → 整图重来（上限 50 次）
  4. 死端 = 恰有 1 个邻居的房，按到出生房的步数降序分配（对齐官方顺序 Boss→商店→宝箱）：
     最远 → Boss 房；次远 → 商店；再次 → 宝箱房；剩余 → 挑战房 / 救援营地 / 黑市或祭坛候选
     死端不足 5 个 → 重 roll（官方 MinDeadEnds=5）
  5. 隐藏房：在与 ≥3 个房相邻、且不与 Boss 房和死端相邻的空 cell 里加权随机
     （邻居越多权重越高；300/600 次失败后逐步放宽——官方同款）；
     不在小地图显示，入口=冲刺撞开有裂纹的墙（《01》§10）
  6. 黑市/祭坛：上一层计量条达标时，把一个剩余死端标记为黑市或祭坛（二者互斥）
产出: grid[13][13] → {type, cleared, visited} + 邻接表
测试断言: 连通无孤岛 / Boss 为最远死端且不与出生房相邻 / 出生房无敌人 /
          各类特殊房 ≤1 / 同种子逐位一致
```

**Boss 大房与网格解耦**：换房是整盒替换（§5），地图网格只管拓扑。Boss 房是死端、只有一扇门，
网格里占 1 格即可，内部按大尺寸（24×16 tile）搭建，小地图上画成大图标。
普通房的 2×1 / 2×2 / L 型大房（多门、可成环）留到 M5，届时按 Rebirth 的做法实现：
遍历房间的所有出口、随机尝试大房型，只对门口那一格做邻居检查但要求整个占位为空，
成功后 95% 概率把该形状移出候选池。

## 7. 渲染层设计（HD-2D 管线）

### 7.1 场景装配（每个房间一个"立体盒"）

```
Y 轴向上（three 默认），地面为 XZ 平面。1 tile = 1 世界单位 = 16 texel（全场同密度）
· 地板：PlaneGeometry（17×11 单位），CC0 16×16 px 图块拼贴，三楼层主题各一图集，MeshStandardMaterial
· 墙体：低多边形 3D 体块（0.8 高），贴像素图块纹理——墙是"实心 3D"，精灵是"面片"
· 实体（玩家/敌/弹/掉落）：PlaneGeometry 面片，只绕 Y 轴转向相机（圆柱 billboard）
· 装饰：水晶/火把/草丛=小 3D 体+发光材质，火把绑定点光（从灯光池分配）
```

### 7.2 精灵面片规范（HD-2D 的关键三件套）

1. **alphaTest 裁切**：`transparent:false + alphaTest:0.5`——写深度，景深/后处理才能正确处理精灵边缘；
2. **参与阴影**：面片 `castShadow=true` + `customDepthMaterial`（`MeshDepthMaterial{map, alphaTest, RGBADepthPacking}`），
   点光下补 `customDistanceMaterial`；材质 `side:DoubleSide` 让两面都投影（八方旅人同款处理）；
   注意：`THREE.Sprite` 不进阴影 pass，**必须用 Plane mesh**；
3. **法线朝天倾斜**：面片法线不取朝向相机，而是向天空方向抬约 60°（本项目初值），
   让平行光/点光在精灵上打出明暗——"像素人被环境光照亮"就是 HD-2D 的灵魂。

### 7.3 灯光

- 环境底光 `HemisphereLight`（天=楼层主题色，地=暖反射）；
- 主 `DirectionalLight`（斜上方投影）。阴影用 `PCFShadowMap`：r183 起 `PCFSoftShadowMap` 对 WebGLRenderer
  已弃用，`PCFShadowMap` 本身就是柔和过滤。**阴影正交盒覆盖整个房间且固定不动**（1×1 房约 20×14 单位）——
  房间是静态盒子，阴影盒不跟随玩家，从根上消除阴影游移；Boss 大房若分辨率不够，改为跟随玩家+按阴影纹素对齐移动；
- 点光池 8 盏（火把/大招/爆炸/掉落光），超出时按"离玩家最近优先"回收；
- 发光体（水晶、敌弹、特效）材质 `emissive` 拉满，喂给 Bloom。

### 7.4 后处理链（postprocessing 装配顺序）

```
RenderPass → [N8AO 高档] → DepthOfFieldEffect(焦点带: 玩家±2.5 格, 景深量=档次)
          → BloomEffect(mipmapBlur, threshold≈0.9) → ToneMappingEffect(AGX)
          → VignetteEffect(≈0.35) → [NoiseEffect 轻颗粒] → SMAAEffect → 输出
```

色彩管理：`renderer.outputColorSpace = SRGBColorSpace`，贴图 `colorSpace=SRGB`；
中间缓冲全部 HDR（`frameBufferType: HalfFloatType`）；色调映射只在链末端做一次（ToneMappingEffect），
渲染器自身不再做。参数初值见《03》§7。

### 7.5 相机与帧循环

- `PerspectiveCamera` fov≈40，**固定偏航/俯仰**（约 -55° 俯角，初值见《03》§3），跟随玩家
  （lerp 0.08 + 朝移动方向前瞻 0.8 格）；
- 渲染插值：实体渲染位置 = `prev + (curr-prev)×α`（α=累加器余量）；
- hit-stop：命中大额伤害时 `timeScale=0.05` 持续 3–5 模拟帧；震屏=相机噪声偏移（衰减包络）；
- Boss 登场/进化演出：相机推拉 + 时间冻结 + 聚光点光（演出期锁输入，渲染照常）。

## 8. 性能预算

| 指标 | 预算 | 手段 |
| --- | --- | --- |
| 帧率 | 60fps（低档机型 30 保底） | 画质档自适应降级 |
| 同屏实体 | ≤80（敌+弹+掉落） | 对象池 + 分帧刷怪波 |
| draw call | ≤150 | 图集合批（同图集共享材质，billboard 实例化绘制） |
| 首包 | ≤6MB（gzip 后） | 只含首层所需：玩家 3 只 + F1 敌人 8 种 + 小刚（约 12 个物种图集）+ 洞窟贴图；后续楼层在当前层游玩时后台预取 |
| 引擎体积 | three 用官方压缩构建 `three.module.min.js` | 无构建链无法 tree-shake，接受整包；postprocessing 低档不加载 |
| 图集 | 单张 ≤2048²，保留原动画全部帧（时长按 AnimData 的 1/60s 计） | 按物种分图集 |
| 内存 | 图集纹理 ≤64MB | 控制同时驻留的图集数；掉落物图标单独小图集 |

## 10. 技术风险与对策

| 风险 | 对策 |
