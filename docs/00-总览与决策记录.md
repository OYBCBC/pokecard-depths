# 00 · 总览与决策记录（ADR）

> **项目代号**：宝可梦·晶穴深处（Pokémon: Crystal Depths，暂定·非官方同人命名）
> **一句话**：以撒式的房间制俯视角动作肉鸽 × 宝可梦素材，用 Three.js 渲染成 HD-2D 像素立体绘本。
> **性质**：免费、非商业、非官方的浏览器同人游戏（与《徽章之路》《像素徽章之路》同一工作区第三作）。
> **文档日期**：2026-11-02（M0 立项）

## 一、项目定位

| 维度 | 决策 |
| --- | --- |
| 玩法内核 | 《以撒的结合》式：房间制地牢探索 → 清怪开门 → 双摇杆走位射击 → 道具构筑滚雪球 → Boss → 下一层 |
| 题材皮 | 宝可梦：训练师带一只同行宝可梦下洞（初始三选一）；进化=形态成长；官方道具/树果=以撒道具；道馆馆主=层 Boss；梦幻=最终 Boss |
| 视觉 | HD-2D（八方旅人式）：像素精灵 2D 面片（billboard）+ 3D 场景灯光/景深/泛光/固定斜俯视相机 |
| 载体 | 纯静态网页（GitHub Pages），点开即玩，免下载免注册 |
| 语言 | 中文界面 + 隐藏英文项（复用缝合像素字体方案） |
| 玩家操作 | 键鼠为主（WASD+鼠标瞄准），手柄/触屏后置到 M4 |

**立项判断**（承接工作区《可行性分析报告》结论，竞品信息核实于 2026-11-02）：

- **品类已有人先发，但窗口还在**：**PokéIsaac**（pokeisaac.com，作者 SrBatai）2026-10-19 刚公布——
  浏览器宝可梦×以撒（宣传 971 只宝可梦、350 道具、12 层、4 人联机、纯像素 2D）。这说明品类需求是真的，
  也意味着"再复刻一个以撒"不够用了。本作的差异化三件套：①**HD-2D 视觉**（对方纯像素 2D；
  据本次调研，浏览器端还没有 HD-2D 风格的宝可梦游戏）②**中文首发**（对方无中文）③**轻量单机**（对方主打
  4 人联机与全图鉴量，我们做 20–35 分钟一局的紧凑塔+构筑深度）。同题材并存有先例：
  2026-10 同月上线的 PokéBonk 与 PokéSurvivor 两款宝可梦割草游戏都攒下了玩家（玩家数为第三方口径）；
- 房间制比割草更"内容可控"：以撒的乐趣大头在道具协同与地图生成，二者都是数据/算法工程，
  恰好是本工作区两作验证过的强项（数据驱动 + 引擎纯函数化）；
- HD-2D 是本作差异化卖点：浏览器上的宝可梦同人几乎都是纯 2D 或纯 3D（"3D 场景+像素精灵"只在
  UE5 桌面同人 Gamma Emerald、Dott 的 HD-2D 概念视频里出现过），"像素精灵站进立体灯光场景"
  自带短视频传播素材（名场面：十万伏特一瞬全屏泛光）。

## 二、技术决策记录（ADR）

| # | 决策 | 选择 | 理由 | 状态 |
| --- | --- | --- | --- | --- |
| ADR-1 | 渲染引擎 | Three.js（基线 r187，2026-10-30 发布） | HD-2D 需要 3D 灯光/景深/斜视相机；可行性报告已验证 PokéBonk 用同栈跑通割草 | ✅ 已定 |
| ADR-2 | 渲染后端 | WebGLRenderer；gfx/ 薄适配层预留 WebGPU | pmndrs/postprocessing **不支持 WebGPU**（上游 issue #524），TSL 后处理生态未稳；WebGL2 覆盖面最大 | ✅ 已定 |
| ADR-3 | 后处理 | pmndrs/postprocessing 6.39.x（Bloom(mipmapBlur)/DoF/Vignette/ToneMapping(AgX)/SMAA/Noise）+ N8AO 2.x（高档可选） | three 自带 EffectComposer 效果弱，社区库是事实标准；详见《02》§7.4 | ✅ 已定 |
| ADR-4 | 工程形态 | 无构建：ES 模块 + import map + 供应商目录 `vendor/` | Pages 纯静态、无 node 环境依赖、改码刷新即生效——沿用前两作工作流 | ✅ 已定 |
| ADR-5 | 语言 | 原生 JS（ES2022+，模块化）+ `node --test` 单测 | 与前两作一致；TS 需要构建链，违背 ADR-4 | ✅ 已定 |
| ADR-6 | 模拟与渲染分离 | 引擎纯函数 + 可序列化状态 + 固定步长 60Hz，渲染层只读状态 | 《徽章之路》验证的架构；回放/测试/换皮三重收益 | ✅ 已定 |
| ADR-7 | 宝可梦动画素材 | SpriteCollab（PMD 风格 8 方向动画） | 8 方向走路/攻击/受击动画是俯视角游戏硬需求，社区无同级替代；**注意"官方拆包件+社区自制件"双层许可（Gen1 基础精灵全部是 CHUNSOFT 拆包件）**，详见《06》§2.1 | ✅ 已定 |
| ADR-8 | 场景贴图 | CC0 像素图块，**16px 基准**（1 tile=1 世界单位=16 texel；DCSS 32×32 作 2×2 大件） | 环境 100% 合规避险：官方图块是任天堂资产，红线不碰；16px 与 PMD 精灵密度匹配 | ✅ 已定 |
| ADR-9 | 音频 | PokeAPI 叫声 ogg + WebAudio 合成音效/BGM；解码失败静默降级（Safari 18.4 前无 Ogg Vorbis；皮卡丘叫声文件实为 MP3 数据，须 fail-soft） | 《像素徽章之路》已验证该管线；《06》§2.2–2.3 列了三个坑 | ✅ 已定 |
| ADR-10 | 地图生成 | 以撒算法移植（13×13 网格 BFS 扩张 + 死端分配特殊房） | 社区拆解文档完备；产出可序列化、可测试 | ✅ 已定 |
| ADR-11 | 数值 | 敌人：种族值换算房间战面板；玩家：以撒六维与官方成长公式；单发伤害再乘官方的威力/克制/STAB/特防乘区 | 老玩家零学习成本，两边心智都保留；详见《01》§8 | ✅ 已定 |
| ADR-12 | 远端仓库 | GitHub `OYBCBC/pokecard-depths`（**待创建**，公开），HTTPS+钥匙串凭据，Pages 部署 | 沿用 pokecard / pokecard-pixel 同模式；命名对齐工作区系列 | ✅ 已定（仓库未建） |
| ADR-13 | 存档与分享 | localStorage 键 `depths-*`；挑战码前缀 `DPT1.` | 与前两作同 origin 不冲突 | ✅ 已定 |
| ADR-14 | 联机 | 不做（首版） | 单人开发带宽有限；以撒内核本就是单人体验；排行榜用挑战码+本机榜起步 | ✅ 已定 |
| ADR-15 | 可换皮 | 素材 manifest + 数据层与代码分离，48 小时可切原创怪包；M4 做一次换皮推演 | 可行性报告的第一架构保险，红线级要求 | ✅ 已定 |

## 五、非目标（No-Go）

明确不做，避免范围蔓延：

1. **联机/多人**（任何形式，含异步）；
2. **官方音乐**、官方图块贴图、官方人物立绘、官方 3D 模型——版权高危区，红线；
3. 商业化、广告、内购、捐助链接（比前两作更保守：本作贴近官方《不可思议的迷宫》品类心智）；
4. 全图鉴 1000+ 支持——首发 40 只上下，名单以 SpriteCollab 覆盖率定（《04》）；
5. 剧情演出大文本——以撒式叙事靠环境与片段，不做 RPG 对话树。
